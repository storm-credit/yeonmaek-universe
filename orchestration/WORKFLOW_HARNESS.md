# Workflow Harness

## 강제 실행 순서

1. **요청 분류** — 정본 변경, 설정 보강, 구조 설계, 감사, 원고, 운영 작업 중 하나 이상으로 분류한다.
2. **정본 권한 확인** — 대상 파일의 승인 등급, 상위 정본, 잠금 상태, 충돌을 확인한다.
3. **Context Pack 생성** — 요청 범위에 맞는 최소 CP를 만들고 원본 경로를 기록한다.
4. **분야별 상세도 확인** — 세계·인물·세력·아이템·미스터리·시간·거리·권한의 차단 공백을 검사한다.
5. **상황별 작법 선택** — 중심 1개, 보조 최대 2개를 고른다.
6. **구조·인과·POV 설계** — 공식 계층의 11필드와 Subact 인과 계약을 작성한다.
7. **연속성 검사** — 시간, 거리, 정보상한, 상태, 영구 손실, 권한을 장부와 대조한다.
8. **독자 경험 검사** — 약속·진행·회수, 정보량, 긴장·이완, 경이, 생활 후과를 검사한다.
9. **맹점·반복·유사성 검사** — Red Team, Anti-Repeat, 직접 모사·오염 검사를 수행한다.
10. **상태 장부 갱신** — 관련 모든 장부와 현재 상태 문서를 갱신한다.
11. **완료 판정** — `COMPLETION_GATES.md`에 따라 S0/S1과 산출물을 확인한다.
12. **GitHub main 반영 확인** — 파일 존재·내용·참조·커밋 SHA와 `main` 도달 여부를 확인한다.

## 되돌림 규칙

설정이 부족하면 Episode나 원고에서 즉석으로 만들지 않는다.

- 장소 공백 → A03
- 마법·기술·질병 공백 → A04
- 문화·종교 공백 → A05
- 기관·경제·법 공백 → A06
- 고유 권리 시스템 공백 → A07
- 인물·관계 공백 → A08
- 세력·적대 공백 → A09
- 아이템·생물 공백 → A10
- 미스터리·복선 공백 → A11
- 구조 공백 → A12

되돌아간 이유와 중단 지점을 `DECISION_LOG` 또는 관련 장부에 남긴다.

## 원고 잠금 분기

현재는 신규 원고가 잠겨 있다. 요청이 원고·대사·장면 본문 생성으로 분류되면 다음을 확인한다.

1. 사용자의 명시적 잠금 해제 지시가 있는가
2. 대상 계층 CP가 있는가
3. S0=0, S1=0인가
4. 사용자 승인 필요 결정이 남아 있지 않은가

하나라도 아니면 집필하지 않고 필요한 설정·구조 단계로 되돌린다.
