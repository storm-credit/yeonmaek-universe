# 소설 프로젝트 PM·RACI·검토 서명 규칙 v0.1

## 1. 단일 책임자

### A00 — 소설 프로젝트 PM·총괄 오케스트레이터

A00이 프로젝트의 단일 `Accountable`이다.

A00의 책임:

- 작가 의도와 성공조건을 작업 계약으로 변환
- 세계관·서사·제작·검증 작업의 범위와 순서 관리
- 필요한 최소 전문 패널 배정
- 후보 4안과 후퇴안 요구
- 충돌 의견을 숨기지 않고 작가 게이트로 올림
- 다음 단계 진입·동결·재개 판단
- 산출물 색인·상태·편차·미해결·인간 검토 추적
- 원고가 설정을 조용히 정본화하지 않게 통제

A00은 세계 규칙·서사·문화·법률의 단독 전문가가 아니며, 전문 리드의 반대 의견을 덮을 수 없다.

## 3. RACI

- `A` Accountable: 최종 통합·상태 책임. 기본 A00.
- `R` Responsible: 실제 설계·분석 책임.
- `C` Consulted: 사전 반박·영향 검토.
- `I` Informed: 결과를 입력으로 받음.
- `H` Human gate: 작가·독자·전문가의 실제 승인/감수.

## 5. 문서 서명 필드

새 핵심 문서는 머리말에 다음을 기록한다.

```yaml
accountable: A00
responsible: [A01]
consulted: [A02, A03, A13, A14, N16]
challenged_by: [A13]
human_gates: [author]
source_of_truth: true|false
status: candidate|provisional|canon|deprecated|human-review
```

기존 문서는 중앙 `artifact-provenance-matrix`에서 소급 관리하고, 내용 수정이 있을 때 머리말로 이동한다.

## 6. 승인 규칙

- 같은 사람이 설계자와 유일 검증자가 될 수 없다.
- `PASS`는 역할 계약상 내부 체크 통과이며 독립 AI 인스턴스나 인간 검토를 의미하지 않는다.
- 문화·법률·안전·의료·상표·실제 독자 반응은 AI가 최종 승인하지 않는다.
- A13 또는 A14가 중대 위험을 열어 둔 상태에서는 다음 단계가 `blocked`다.
- N16/P09 영향 검토 없이 이름·규칙·연표·결말을 조용히 덮어쓰지 않는다.
- 작가 승인 없는 candidate→canon 승격은 금지한다.
