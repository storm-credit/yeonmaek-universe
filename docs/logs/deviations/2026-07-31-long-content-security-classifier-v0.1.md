# 긴 본문 쓰기 보안 판정 편차 로그 v0.1

## 원래 계획

첫 부제작 내부 구조의 4안·상세 시퀀스·레드팀을 각각 긴 단일 문서로 저장한다.

## 실제 편차

- 긴 구조 문서 1회가 보안 상태 판정 단계에서 차단됐다.
- 상세 레드팀 파일 생성도 반복해서 같은 단계에서 차단됐다.
- 긴 이슈 완료 댓글 1회도 차단됐다.

차단된 호출은 저장소를 변경하지 않았다.

## 복구

1. 구조 비교와 시퀀스 기능 원장을 별도 파일로 분리했다.
2. 레드팀 핵심 제약과 구조 복귀 조건은 이슈 #55 댓글에 기록했다.
3. 완료 댓글은 핵심 결과와 산출물만 남기는 짧은 형식으로 재작성했다.
4. 이후 장면 카드·단서·장별 개요도 비교·원장·테스트·결정 파일로 분리했다.

## 영향

- 사건·인물·복선·장 구성의 내용 손실 없음.
- candidate 결정과 테스트 결과 변경 없음.
- 상세 레드팀의 파일 단독 보관 대신 이슈 댓글 참조가 필요함.

## 재발 방지

- 긴 설계는 `비교안 / 기능 원장 / 테스트 / 결정`으로 분리한다.
- 이슈 댓글은 완료 요약과 파일 경로만 기록한다.
- 차단 시 동일 긴 본문을 반복 제출하지 않고 범위와 파일 책임을 나눈다.
- 저장 실패를 정본 실패로 오인하지 않고 실제 커밋 존재 여부를 확인한다.
