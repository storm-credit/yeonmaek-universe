# 원고 수정 단계 도구 편차 로그 v0.1

## 편차 A — GitHub 코드 검색 색인 지연

### 계획

최신 원고에서 `모르다`, `확정`, `가능성`, `대답하지 않았다` 반복을 저장소 검색으로 정량 확인한다.

### 실제

직전 생성 파일이 코드 검색 결과에 나타나지 않았다.

### 대응

- 최신 장 파일을 문맥 단위로 직접 비교
- 10·12·13·14장 집중 수술
- 정확한 빈도는 로컬 원고 묶음 또는 출판 편집 도구가 준비되면 재측정

### 영향

구조·원고 내용 손실 없음. 반복어 검사는 정량이 아닌 수동 문맥 감사 상태다.

## 편차 B — 문자 수 자동 계측 불가

### 계획

15장 전체의 공백 포함 문자 수·단어 수·원고지 매수를 자동 계산한다.

### 실제

작업 컨테이너에 GitHub CLI가 없고 외부 네트워크도 사용할 수 없어 원고 파일을 로컬로 묶지 못했다.

### 대응

- GitHub compare의 파일별 추가 라인으로 상대 분량만 계산
- 최신 원고 약 3,319라인
- 2분권 후보 약 1,725/1,594라인, 52:48
- 최종 분권은 문자 수·원고지·판형 인간 편집 게이트로 유지

### 영향

분권의 구조적 경계는 검증했으나 최종 제작 분권은 미확정이다.

## 편차 C — 준비도 파일 stale SHA

### 계획

원고 완료 뒤 준비도 매트릭스를 v0.3으로 갱신한다.

### 실제

이전 콘텐츠 SHA로 갱신해 GitHub가 409로 쓰기를 거부했다.

### 대응

- 최신 파일을 다시 읽음
- 최신 blob SHA로 정상 갱신
- 강제 덮어쓰기 없음

### 영향

내용 손실·정본 충돌 없음.

## 재발 방지

- 새 원고 검색은 인덱싱 지연을 전제로 fetch/색인 파일을 우선 사용
- 분량 판단은 라인 수를 최종 판형 근거로 사용하지 않음
- 기존 파일 갱신 전 항상 최신 blob SHA 재조회

## 종료 상태

- A: 수동 감사로 임시 해결, 정량 편집 단계 재검사
- B: 출판 편집 게이트로 이관
- C: 해결
