# Canon Constitution

상태: **P0 운영 정본**
발효일: 2026-08-08
적용 저장소: `storm-credit/yeonmaek-universe`
운영 브랜치: `main`

## 1. 프로젝트 목적

이 저장소는 장편소설 《겹길의 아이들》의 세계관, 설정집, 이야기 설계도, 원고, 검수 기록을 **정본 우선 계층형 스토리 오케스트라** 방식으로 관리한다. 목표는 설정보다 원고가 앞서거나, 하위 문서가 상위 결정을 덮거나, 출처가 불명확한 자료가 정본에 섞이는 일을 막는 것이다.

## 2. 정본 우선순위

충돌 시 아래 순서를 적용한다.

1. 현재 사용자가 직접 확정한 내용
2. 사용자가 이후 명시적으로 승인한 결정
3. 이 Canon Constitution
4. Canon Amendment와 Decision Log
5. 상태 장부
6. 분야별 설정집
7. 전체 이야기 설계도
8. Context Pack과 작법 배치
9. 원고
10. 폐기·참고 자료

같은 등급끼리 충돌하면 더 최근의 명시적 승인, 더 좁고 구체적인 결정, 출처가 더 명확한 기록 순으로 판단한다. 그래도 판단할 수 없으면 작업을 중지하고 충돌 항목·영향·선택지를 보고한다.

## 3. 현재 원고 잠금 상태

- 상태: **LOCKED — 신규 집필 금지**
- 잠금 범위: 신규 원고, 대사, 장면 본문, 후속 회차 초고
- 보존 범위: 기존 원고와 검수 파일은 삭제·축약·재작성하지 않는다.
- 현재 확인 기준: 제1부 1~11장 원고와 Act 1·2 통합 감사가 `main`에 존재한다.
- 잠금 해제 조건: 사용자의 새로운 명시적 집필 허가와 해당 단위의 S0=0, S1=0, 필수 Context Pack 완성.
- 잠금 상태에서도 가능한 작업: 정본 정리, 설정 보강, 계층 매핑, 장부 갱신, 감사, 템플릿 정비.

## 4. 공식 이야기 계층

`Series → Grand Act → Volume Act → Arc → Subact → Episode → Scene`

기존 구조는 다음과 같이 보존·매핑한다.

- Series: 작품 전체
- Grand Act: 기존 5부
- Volume Act: 기존 15 Act
- Arc: 각 Volume Act 아래의 기능성 Arc 래퍼. 초기 마이그레이션에서는 Volume Act당 1개, 총 15개이며 세 Subact의 국소 변화와 반복 방지를 관리한다.
- Subact: 기존 45 Subact
- Episode: 기존 90장
- Scene: 장별 씬 비트와 실제 장면

각 계층은 다음 필드를 가진다.

`Promise / Goal / Opposition / Choice / Cost / Revelation / Reward / Loss / State Change / Next Cause / Anti-Repeat`

기존 문서에 없는 필드는 임의로 채우지 않고 공백 장부에 기록한다.

## 5. Subact 인과 계약

모든 Subact는 국소 문제를 해결하거나 명확히 실패해야 한다. 성공·실패·부분 성공의 비용 또는 손실이 다음 Subact의 직접 원인이 되어야 한다. 단순한 정보 제시, 분위기 전환, 두 Episode의 묶음만으로는 Subact 완료가 아니다.

필수 확인:

- 종료 시점의 상태 변화가 명시되어 있는가
- 다음 Subact가 그 변화 없이는 같은 방식으로 시작될 수 없는가
- 동일한 오판·해결·훅 조합을 반복하지 않는가
- Reward와 Loss가 둘 다 추적되는가

## 6. 정본 변경 절차

1. 변경 요청을 분류한다.
2. 영향받는 상위 정본과 장부를 확인한다.
3. 기존 출처와 승인 등급(P0/P1/P2/Q/X)을 기록한다.
4. 충돌과 하위 파급을 분석한다.
5. 사용자 승인 필요 여부를 판정한다.
6. 승인된 변경은 `CANON_AMENDMENTS.md`와 `DECISION_LOG.md`에 기록한다.
7. 관련 분야 문서, 계층 설계도, 장부, 상태 문서를 같은 변경 묶음에서 갱신한다.
8. 검증 후 `main` 반영 SHA를 확인한다.

## 7. 사용자 승인 필요 조건

다음은 자동 확정하지 않는다.

- 세계의 핵심 규칙, 결말, 주인공 정체성·욕망·최종 상태 변경
- 5부·15 Act·45 Subact·90장 수와 대응 관계 변경
- 기존 원고의 사건 인과·대사·장면 본문 변경
- 인물 사망, 영구 손실, 관계 파기, 핵심 비밀의 회수 시점 변경
- 고유명·시대·배경 국가·주 독자·플랫폼 분량의 새 P0 확정
- 차단 항목을 예외로 통과시키는 결정
- 기존 P0 또는 Canon과 직접 충돌하는 선택

## 8. 충돌 해결 규칙

- 하위 문서는 상위 정본을 수정하지 못한다.
- Context Pack, 프롬프트, 스킬, `CLAUDE.md`, `AGENTS.md`는 정본 전달 수단이지 정본 자체가 아니다.
- 원고가 설정집과 충돌하면 원고를 근거로 설정을 소급 발명하지 않는다.
- 상태 문서의 “완료” 표기가 원문 상태(`candidate`, `canon:false`)와 충돌하면 완료 표기를 보류하고 감사한다.
- 파일명과 내부 제목이 충돌하면 내용·참조·이력을 확인한 뒤 손실 없는 이름 변경만 허용한다.
- 직접 충돌이 해소되지 않으면 S0로 등록하고 원고·하위 설계를 중지한다.

## 9. 기존 오염 자료 격리

다음 자료는 출처 확인과 사용자 승인 없이 재사용하지 않는다.

- 기존 200화 구조
- 기존 7부제
- 기존 117장·234장면
- 다른 프로젝트의 인물명·사건·복선·결말
- 특정 유명 작품의 장면·문체·관계·조직 구조 직접 모사
- 출처가 불명확한 생성물, 압축 payload, 임시 workflow 산출물

의심 자료는 삭제보다 격리를 우선하며 `Q` 또는 `X`로 표시하고, 정본 경로에서 참조하지 않는다.

## 10. 완료 원칙

- 실행하지 않은 에이전트를 실행했다고 보고하지 않는다.
- 미완료 작업을 완료로 보고하지 않는다.
- 모든 완료 판정은 `orchestration/COMPLETION_GATES.md`와 상태 장부를 따른다.
- 신규 원고 잠금이 해제되기 전에는 후속 원고를 만들지 않는다.
