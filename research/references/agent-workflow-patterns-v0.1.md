# 에이전트 작업 방식 참고 분석 v0.1

## 목적

외부 저장소의 소프트웨어 개발 방식을 세계관·서사 설계 절차로 번역한다. 코드·문구·소설 설정을 복제하지 않고 문제 해결 기능만 가져온다.

## 비교표

## 공통 원칙으로 합성

1. **먼저 이해한다**: 현재 정본·의도·의존성을 읽지 않고 새 설정을 만들지 않는다.
2. **가정을 보인다**: 가정과 불확실성을 숨기지 않는다.
3. **대안을 구조적으로 나눈다**: 이름만 다른 4안을 금지한다.
4. **가장 단순한 안을 포함한다**: 확장 가능성보다 현재 질문을 먼저 해결한다.
5. **성공조건으로 실행한다**: `좋다`가 아니라 통과 가능한 테스트를 만든다.
6. **부분 수정 전 전체 영향을 본다**: 관련 복선·인물·지역·기관을 확인한다.
7. **설계와 실행을 분리한다**: 설계 문서와 구현/실행 계획을 덮어쓰지 않는다.
8. **결정과 실패를 기억한다**: 폐기 이유와 변경 경로를 지우지 않는다.
9. **분석 예산을 조절한다**: 긴 자료는 전체 희소 스캔 후 핵심만 정밀 분석한다.
10. **검토 뒤 다음 게이트로 간다**: 명세 적합성과 품질 검토를 분리한다.

## 소설 설계 전용 변환

### 코드 테스트 → 서사 테스트

- 단위 테스트 → 규칙의 경계 사례
- 통합 테스트 → 사건·인물·복선·결말 연결
- 회귀 테스트 → 기존 부제작과 정본 충돌 여부
- 성능 테스트 → 독자 정보량·용어 밀도·설정 공개 예산
- 보안 테스트 → 문화 전용·권리 침해·은폐 구조의 윤리 위험

### 구현 계획 → 설계 실행 큐

각 게이트는 다음 필드를 가진다.

- 입력 정본
- 결정 질문
- 4안
- 함정 체크
- 테스트
- 레드팀
- candidate
- 후퇴안
- 변경 영향
- 다음 의존 게이트

## 경고

- 참고 저장소의 인기나 권위를 근거로 이 프로젝트에 무조건 적용하지 않는다.
- 질문 절차가 이미 확인된 사용자 의도를 다시 묻게 만들지 않는다.
- 자동 진행이 `canon` 승인과 현지 인간 감수를 우회하지 않는다.
- 지식 그래프와 메모리 문서 자체가 목적이 되어 설정집이 비대해지지 않게 한다.
