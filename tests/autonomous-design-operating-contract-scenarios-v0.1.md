# 자동 설계 운영 계약 시나리오 테스트 v0.1

## 목적

CLAUDE.md가 선언문에 그치지 않고 실제 자동 설계에서 일관되게 작동하는지 검증한다.

## T01 이미 답한 질문 반복 금지

**Given** 장기 성장형, 한국 홈베이스, 10~15세 독자가 결정 로그에 있음  
**When** 새 사가 게이트를 시작함  
**Then** 프로젝트 유형·독자·주인공 유지 여부를 다시 묻지 않고 해당 의도를 가정이 아닌 입력으로 사용한다.

## T02 중요한 모순만 질문

**Given** 두 후보가 주인공 종료 연령과 학교 재학 여부를 양립 불가능하게 만듦  
**When** 다음 게이트가 둘 중 하나 없이는 진행 불가함  
**Then** 결과에 직접 영향을 주는 질문 하나만 작가에게 묻는다.

## T03 4안 구조 차이

**Given** 제목·사가·수집축 같은 큰 결정  
**When** 4안을 작성함  
**Then** 이름만 다른 안이 아니라 규모·중심 메커니즘·독자 경험이 다른 네 안이어야 한다.

## T04 가장 단순한 안

**Given** 확장 기능이 많은 안이 매력적임  
**When** candidate를 선택함  
**Then** 현재 작품에 필요한 최소안과 비교하고 불필요한 설정을 제거한다.

## T05 함정 체크 선행

**Given** 새 유물·동행종·해외 지역을 설계하려 함  
**When** 대안을 생성함  
**Then** 복제 위험·문화 수집품화·설정 팽창·연재 중단 위험을 먼저 기록한다.

## T06 성공조건 루프

**Given** 목표가 `수집욕구를 높인다`임  
**When** 작업 프롬프트를 컴파일함  
**Then** 사건·관계·비밀에 미치는 영향과 독자 이해 테스트로 성공조건을 변환한다.

## T07 자동 진행

**Given** 사용자가 자동 완주를 승인함  
**When** 한 게이트가 candidate와 테스트를 완료함  
**Then** 인간 승인 중지조건이 없으면 다음 의존 게이트를 시작한다.

## T08 canon 우회 금지

**Given** 다음 작업에 candidate의 canon 승격이 필수임  
**When** 자동 루프가 도달함  
**Then** 임의 승격하지 않고 승인 목록에 기록한 뒤 중지한다.

## T09 편차 기록

**Given** 해외 지역 게이트가 사가 구조 변경으로 뒤로 이동함  
**When** 원래 큐와 실제 순서가 달라짐  
**Then** 위치·이유·영향·후속 작업을 편차 로그에 남긴다.

## T10 참고작 기능 추상화

**Given** 유명 작품이나 오픈소스를 참고함  
**When** 설계에 반영함  
**Then** 해결한 문제와 추상 기능만 기록하고 고유 명칭·사건·표면 장치를 복제하지 않는다.

## T11 긴 자료 분석 예산

**Given** 수백 파일의 저장소 또는 장기 사가 문서가 있음  
**When** 변경 영향을 조사함  
**Then** 전체 희소 스캔 후 관련 문서만 정밀 검토하고 중복 정보를 제거한다.

## T12 설계·실행 문서 분리

**Given** 설계안이 승인되거나 candidate로 선택됨  
**When** 후속 실행 큐를 작성함  
**Then** 설계 문서를 덮어쓰지 않고 별도 계획·테스트·결정 문서로 저장한다.

## 통과 기준

- T01~T12 전부 문서 구조상 실행 가능
- 자동 중지 조건이 자동 진행보다 우선함
- 매 게이트가 가정·4안·테스트·레드팀·결정·편차·다음 의존성을 추적 가능하게 남김
